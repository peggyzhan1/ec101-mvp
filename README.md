# EC101 数据底座与费用运营台

本项目将快马、舟谱源文件转换为统一工作簿，导入 SQLite 后由唯一的实际费用核算引擎生成费用结果。

## 本地运行

```bash
python -m venv .venv
.venv/bin/pip install -e '.[dev]'
ec101-convert kuaima --dealer 经销商 --source order=订单.xlsx --output output
ec101-api --db ec101.db --archive-dir archives
npm --prefix web install
npm --prefix web run dev
```

先启动 `ec101-api`，再启动 Web 开发服务器。开发服务器会将 `/api` 和 `/health` 自动转发至 `http://127.0.0.1:8000`；如 API 部署在其他地址，可设置 `VITE_API_BASE_URL`。

桌面转换入口为 `python desktop/app.py`。Windows 打包可执行 `desktop/build_windows.ps1`。

转换输出包含 `standard.xlsx`、`sources.zip` 与 `conversion_report.txt`。运行导入 API 时，来源归档路径应由部署方纳入备份；SQLite 数据库和归档文件均不应提交到仓库。

## 客户费用确认流程

操作顺序固定为：**客资快照 → 应发名单 → 问卷答卷 → 对账**。

1. 从数采通同步太古客资和客资映射快照，并以第三方数据中实际出现过的客户编号校验映射。
2. 导入周期应发名单。系统按“费用周期 + 太古客户编号”汇总，每名客户只保留一条应发金额。
3. 活动结束后导入问卷星答卷。问题必须是“是否收到本期全部协议费用”，不做订单、销售凭证或单张券级确认。
4. 在费用确认工作台查看应发、已提交、未提交、已收到、未收到和冲突，并处理名单外答卷、未匹配及多义映射。

对账以应发名单为左表，因此未提交问卷的应发客户不会消失；名单外答卷只进入异常清单，不增加应发客户数或应发金额。

### 隐私与文件管理

问卷中的答卷手机号仅用于受限核验，页面和对账接口不得展示。真实客资、手机号、问卷文件、导出名单和 SQLite 数据库均属于敏感资料，不得提交到 Git 仓库；生产环境应限制访问并按内部制度备份和留存。

## 范围

费用结果只来自实际活动核销与优惠券核销，由后端唯一引擎计算。未关联订单的券会展示在券汇总和未关联券清单中，但绝不进入释放候选。
